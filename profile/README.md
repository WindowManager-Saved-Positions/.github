## How WindowManager Sits

WindowManager does not replace the taskbar pin, the display arrangement, or the manual drag you already repeat each morning. It sits beside them as a named layout desk for one job: which saved positions are live, which window restore still matches the desktop map, and what the next person should read before the next hunt for lost windows.

## Traffic Light

| Signal | On the WindowManager board | What you do |
|--------|----------------------|-------------|
| Green | Named desk, short live position list | Continue the same desktop map |
| Amber | Two mornings mixed in one restore | Split the map before you save |
| Red | No title, no note, windows lost | Stop and name the layout first |

## Open Order

1. Open the last WindowManager layout desk, not a new empty desktop map.
2. Read the saved positions and the last handoff.
3. Finish one visible window restore inside WindowManager.
4. Write what changed, then close with fewer lost windows than you found.

## Desk Fit

| Who | What WindowManager holds |

## After a Week

A week in WindowManager is not a larger hunt for lost windows. It is the same title, a shorter live desktop map, and a note that still makes sense on Monday morning. Take finished restores off the live set so the next visit starts on the saved positions that are still open.

## Sign-off

- [ ] The WindowManager workspace name is short enough to scan
- [ ] Only live positions sit on the map
- [ ] A second person can read the restore handoff

## Field Note

WindowManager is easier to trust when the layout desk stays smaller than the lost-window hunt it came from. Name the map, keep the live saved positions, finish one visible restore, and write what changed.
